# RV Files Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the Pingvin Share X fork (`Legendofallpro/RV-files`) into "RV Files", which meets the PS2 brief and rubric. It adds server-generated links, download counts, revoke, clear messages, enforced limits, a file blocklist, a tripwire auto-revoke, a recipient safety card and a redesigned UI, and it is deployed on Railway.

**Architecture:** We keep Pingvin's NestJS + Prisma + SQLite backend and its Next.js 15 (pages router) + Mantine 6 frontend, packaged as one Docker image. New logic that can be pure goes into small util modules with unit tests (blocklist, ID generation, tripwire decision, quota resolution). Services, guards and controllers call into them. A curl script (`scripts/attack-demo.sh`) is the end-to-end test, and it is also the live judge demo.

**Tech Stack:**
- Backend: NestJS 10, Prisma (SQLite)
- Frontend: Next.js 15, React 18, Mantine 6, plus Tailwind CSS 4 (preflight off) and framer-motion
- Copy-paste components from RareUI
- Unit tests: Node 24's built-in `node --test` (native TS type-stripping)
- Deploy: Railway with a volume

**Spec:** `docs/superpowers/specs/2026-10-28-ps2-file-sharing-design.md`. Read it first: it holds the reasons behind every task.

## Global Constraints

- Limits:
  - Max share size **10 MB** (`share.maxSize` = `10000000`).
  - Default per-user quota **50 MB** (new key `share.defaultStorageQuota` = `50000000`).
  - `share.maxExpiration` = `7 days`.
  - `share.defaultExpiration` = `1 day`.
- Share IDs: server-generated `crypto.randomBytes(16).toString("base64url")` (22 chars, 128 bits). Client-supplied IDs are ignored.
- Blocked extensions (case-insensitive, any extension in the name): `exe bat cmd sh ps1 js html htm svg xhtml msi scr jar apk dll`.
- Every file response carries `X-Content-Type-Options: nosniff` and `Content-Security-Policy: sandbox; default-src 'none'; img-src 'self'; media-src 'self'`.
- Tripwire defaults (all config keys under `share.`):

  | Key | Default |
  |---|---|
  | `tripwirePasswordLimit` | 5 |
  | `tripwireDownloadLimit` | 20 |
  | `tripwireDistinctIps` | 5 |
  | `tripwireWindowMinutes` | 10 |

- Revocation reasons (exact strings):
  - `Revoked by owner`
  - `Auto-revoked: too many wrong passwords`
  - `Auto-revoked: unusual download activity`
- IPs are stored only as `sha256(ip + internal.jwtSecret)` hex.
- Error codes the frontend switches on:
  - `share_not_found`
  - `share_expired`
  - `share_removed` (the message carries `removedReason`)
  - `share_max_views_exceeded`
  - `share_password_required`
  - `wrong_password`
- App name in the UI: **RV Files**. Keep the BSD-2 `LICENSE`, and credit upstream in the README.
- Do not upgrade React or Mantine. Drop any RareUI component that needs React 19.
- New UI strings go in English only (`frontend/src/i18n/translations/en-US.ts`, `backend/src/i18n/en-US/*.json`).

## Review Focus

1. **The zip download path (`GET /shares/:shareId/files/zip`)** must respect revocation and expiry, and must count downloads and access events exactly like the single-file path. The test lives in Task 11 (attack-demo: revoked share zip → 404/403).
2. **Range requests (video/audio scrubbing and resumed downloads)** must not inflate the download count or trip the burst rule. Count only when `!file.range`, matching the existing `notifyRecipientDownload` condition. Tested in Task 6.
3. **Tricky file names** must be blocked: `evil.HTML`, `a.pdf.exe`, `a.html.` (trailing dot), `a.html ` (trailing space), and `.htaccess`-style names. Tested in Task 2.
4. **Shares with "never" expiry (unix 0)** may still exist from before the limits changed. The guards must treat them as non-expired (existing behaviour), and the safety card must show "No expiry", not a 1970 date. Tested in Tasks 5 and 9.
5. **Behind Railway's proxy**, the real client IP must be used (`TRUST_PROXY=true`). Otherwise every visitor hashes to one IP, the burst rule never fires, and rate limits hit everyone at once. Tested in Task 11 (attack-demo sends distinct `X-Forwarded-For` values and expects the burst revoke).

- **Backend track:** Tasks 1→2→3→4→5→6. These share `share.service.ts` and the guards, so they run sequentially.

### Task 11: Merge tracks, attack demo, fresh deploy

  1. upload `evil.html` → 400 blocked type
  2. upload `a.pdf.exe` → 400 blocked type
